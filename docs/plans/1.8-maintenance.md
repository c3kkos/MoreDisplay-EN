# 1.8 plan: cleanup and new launcher icon

Status: **approved** (icon background `#FFF6E5`; started right away).

## Goal

A maintenance release: **no new features and no behaviour changes**, except the new launcher icon. The code
gets easier to read, safer to change, and checked automatically. Start only after casting is confirmed working on
the tablet, so the cleanup doesn't mix with open bugs.

## 1. Launcher icon from the repository logo

- The rainbow TV with "MD" (`.github/logo.svg`) becomes the app's **adaptive icon**: the logo is converted to an
  Android vector drawable (sharp at every size) on a plain background layer, scaled so its widest points stay
  inside Android's 66 dp safe zone. Every launcher shape works: circle, squircle, rounded square (see
  `icon-preview.png`).
- Background: warm light `#FFF6E5` (proposed; light blue `#E8F4FF` or white are in the preview too).
- **Themed icon** (Android 13+, "Material You" icons): a one-colour silhouette of the TV and the letters.
- The old bitmap icons (`mipmap-*/ic_launcher*.webp`) are regenerated from the same logo for launchers that still
  use them.
- The notification icon, the eye tile and the widget keep their current eye symbols.

## 2. Responsiveness

- The app's main thread currently waits up to 1.5–2 s for the daemon in a few places (closing the eye, stopping
  a cast, switching the eye between the daemon and the cast). If the daemon is slow, the screen freezes for that
  long. These become background work with the same ordering guarantees.

## 3. One place for hidden Android APIs

- `ActivityTaskManager` (focus, top task), `InputManager`/`InputManagerGlobal` (touch injection),
  `DisplayManagerGlobal` (display list), the audio policy classes and the `InputEvent.setDisplayId` call are
  reached by reflection in six files, each with its own error handling. They move into one `HiddenApi` helper
  with the version differences (Android 10–16) and consistent log lines, so the next "works on 12L but not on 14"
  problem is quick to trace.
- The hook logic itself (visibility, launch, orientation, recording, accessibility, events) is **not rewritten**:
  it is proven on the tablet and hooks can only be tested on a device. Only names and comments may be touched.

## 4. Less duplicated plumbing

- Eye surface, cast sound and touch each pass a pipe or surface to the daemon the same way, with three copies of
  the same "try each channel" loop in `DisplayRepository`. One shared helper replaces them.
- The Shizuku interface method `attachViewer` now carries all three: renamed to `sendWithExtras` (internal
  protocol version 23, so the Shizuku service restarts once by itself).

## 5. Smaller viewer

- `ViewerActivity` handles picture-in-picture, two picture sources (daemon or cast hub), touch and Back in one
  file. It is split into a picture-source part, a touch part and the activity, without changing behaviour.

## 6. Leftovers

- Remove: the encoder's "repeat last frame" setting (the frame hub does it now), an unused property in the cast
  pipeline, stale notes inherited from the original, fully-qualified class names written inline.
- Keep the `docs/plans` files as history.

## 7. Automatic checks

- Android's code checker (**lint**) runs in the GitHub build; real errors fail the build, the rest is reported.
- Unit tests around the moved code (the shared channel helper, the hidden-API version selection where it is pure
  logic). All existing tests keep passing.

## Testing

- GitHub build, lint and unit tests must pass.
- On the tablet: a quick regression pass of everything (create/remove display, policies incl. Open on and
  Landscape, eye + touch, tile/widget/adb, cast, reboot restore). The release notes will list it as a checklist.
