# 1.4 plan: watch a virtual display in picture-in-picture (view-only)

Status: **proposed**, waiting for approval before implementation. Touch control is out of scope (a later version).

## Goal

An app runs hidden on a MoreDisplay virtual display (for example an HD display the built-in screen can't
match), whitelisted so it sees only that display. The user wants to **watch what the app is doing** in a
picture-in-picture window on the built-in screen, and turn that view on and off at will, **without the
virtual display or the app on it being affected in any way**.

## What the user sees

- An **eye** toggles the viewer for a display. Eye on: a real Android PiP window shows the display live.
  Eye off (or the PiP's close button): the window disappears.
- The PiP window is Android's own: drag it anywhere, pinch to resize, tap to **expand to full screen** and
  shrink back, as often as wanted. It keeps the display's aspect ratio (16:9 etc.).
- Everything on the virtual display keeps running exactly as before, whether the eye is on or off.

### The four eye controls

All four exist; **Settings → Eye controls** has a switch for each, so the user chooses which ones to use.

| Control | Where | Behaviour |
| --- | --- | --- |
| (a) Eye button | Each virtual display card in the Displays tab | Toggles the viewer for that display; filled eye while watching. |
| (b) Quick Settings tile | Notification shade, added by the user | One tap toggles the viewer for the **last watched display**; long-press opens MoreDisplay. Shown as unavailable when the control is switched off or there is no display. |
| (c) Home-screen widget | Home screen, added by the user | Shows an eye per display (or one chosen display); tap toggles. Shows "Disabled in Settings" when switched off. |
| (d) adb command | `adb shell am start -n io.github.ynkcc.moredisplay/.CommandActivity --es action eye --ei display_id N --es state on\|off\|toggle` | For scripts. Refused with a clear message when switched off. |

Defaults: all four enabled. The tile and widget only appear once the user adds them in the system UI, so
they are opt-in by nature; the switch disables them even when added.

## How it works

### Swapping the output, not touching the display

Every MoreDisplay virtual display already sends its frames to an output surface: today a "sink" that
discards them (the display must have an output or Android switches it off and the apps on it stop drawing).
The eye only changes **where the frames go**, with `VirtualDisplay.setSurface(...)`:

- **Eye on**: the viewer's surface becomes the display's output.
- **Eye off**: the display goes back to its sink.

The display is never recreated, resized or removed: same id, resolution, density and flags. Swapping
directly from one surface to another keeps the display ON throughout, so the app never sees it switch off.

### Full resolution

The viewer asks for frames at the display's **full size** (`SurfaceHolder.setFixedSize(width, height)`) and
lets the screen's compositor scale them into the PiP window. The display never adapts to the window, so the
app sees the same display either way, and full-screen mode shows as much detail as the panel can.

### Getting the surface to the daemon

Both existing channels carry only serialized bytes, so the surface needs its own path:

- **Vector (system_server)**: the request is a `ContentResolver.call` with a `Bundle`; the surface (a
  `Parcelable`) and a binder token travel in the same `Bundle` next to the request bytes. The provider hook
  already receives that `Bundle`.
- **Shizuku**: two new methods on `IDaemonRpc`: `attachViewer(displayId, Surface, IBinder token)` and
  `detachViewer(displayId)`. `DAEMON_VERSION` goes up so the Shizuku daemon is restarted with the new interface.

### A viewer that dies must not freeze the app

The viewer passes a binder token; the daemon watches it (`linkToDeath`). If the viewer crashes or is killed
while attached, the daemon switches the display back to its sink immediately. The same happens if the
display is removed while being watched. Only one viewer per display; attaching a new one replaces the old.

### Staying invisible to the watched app

- No new display is created and no MediaProjection is involved, so the app gets no "being recorded" signal.
- Swapping a display's output may make Android send a "display changed" event to apps listening for display
  events, even though nothing about the display changes. On the Vector channel, MoreDisplay already
  intercepts display events; it will swallow the change event caused by an eye swap, for every app except
  MoreDisplay itself. (Not possible on the Shizuku channel, which has no hooks; documented as a limitation.)
- Unchanged by the viewer: the app can still see it runs on a display other than #0, and #0 stays in its
  display list (hiding it crashes apps).

## Limitations to document

- View-only: touches on the PiP window do nothing yet.
- Protected content (DRM video, apps that block screenshots) shows black, as with any mirroring.
- Small extra GPU/battery cost while the viewer is open; none when it's closed.
- Event hiding only on the Vector channel.

## Testing

- Unit tests (JVM, run by CI): viewer bookkeeping (one viewer per display, replace, detach on death/removal),
  eye-control settings, adb argument parsing.
- On the device (user): eye on/off from each control; expand/shrink; app on the display keeps running
  throughout; force-stop MoreDisplay while watching (display must keep working); reboot with the eye on
  (displays come back, eye off).
